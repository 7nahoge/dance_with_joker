# ジョーカーと秘密のワルツ

白髪のジョーカーと踊る、2レーンのブラウザー用リズムゲーム。音楽は提供音源から作成した `assets/joker_music.wav` を使用します。外部ライブラリ・API・バックエンドは使いません。

## 起動

ローカルHTTPサーバーで開き、「舞踏会をはじめる」を押してください。インターネット接続は不要です。音源は開始ボタンを押した後に読み込み、カウントインの終了時に再生します。

Pythonがある環境では、このフォルダーから `python -m http.server 8000` を実行し、`http://localhost:8000` を開いてください。VS CodeのLive Serverなど、静的ファイルを配信できるサーバーでも起動できます。`index.html` の直接オープン（file://）では音源を取得できないため、画面に案内を表示します。

## 操作

- 左は F、右は J。下部の左右ボタンはタップ・クリックにも対応。
- カードの中心と金色の判定ラインが重なる瞬間に入力。
- Perfect：±80ms、100点。Good：±160ms、60点。Miss：160ms超過。
- 一時停止ボタンまたは Esc で中断。再開ボタンで再開。タブを離れると自動停止。
- 右上で音量・ミュートを変更できます。

## 構成と仕様

- `index.html`：タイトル、ゲーム、結果、遊び方、中断画面。
- `style.css`：劇場をイメージしたレスポンシブレイアウト。PCは左右、700px以下は上下配置。
- `js/game.js`：Web AudioによるWAV再生と判定・描画。元音源を1.05倍速（157.5 BPM）で再生し、プレイ時間は60秒。前に6拍約2.29秒のカウントイン。固定150ノーツ、満点15000点。
- `assets/joker_music.wav`：提供音源の先頭・末尾の静かな部分を除き、重なりなし（クロスフェード0秒）で繰り返しをつないだ63秒の連続音源。ゲーム中はループせず1回だけ再生し、開始30ms・終了150msでフェードします。PCM 16bit・44.1kHz・ステレオ。再生成用の音源は `source/joker_movie.wav` に一本化しています。元のM4Aとデコード後の音声が一致することを確認済みです。カウントインの合図のみ合成音を使用。譜面は音源の立ち上がりに合わせて作成しています。
- `js/build-music.cjs`：連続音源と譜面の作成スクリプト。`node js/build-music.cjs` で再生成できます。再生速度・音程は変更しません。
- `assets/joker.png` / `assets/joker_movie.mp4`：提供素材はこの場所に集約。相対パスで参照し、`object-fit: contain` で縦横比を維持。動画はミュート・ループでレーンと別領域に配置。
- `js/verify.cjs`：Node.js標準機能だけを使う自動検証。`node js/verify.cjs` で実行。
- `source/joker_movie.wav`：音源の再生成に使う約10秒の元音声。ゲームから直接は読みませんが、`js/build-music.cjs` に必要です。開発用スクリプトとこの元音声は、今後の調整のために残しています。
- `js/music-chart.js`：主旋律の推定オンセットに基づく固定譜面。四分音符の拍列はカウントインとテンポの算出だけに使い、カードは高音域の音の出だしに配置します。音源の切り取り・繰り返し・再生速度を判定時刻に反映します。元音源の9秒ごと（プレイ中は約8.57秒ごと）のフレーズで13→17→20→22→24→26→28枚と増やし、合計150枚にしています。強い旋律音中心の序盤から、弱い装飾音も含む終盤へ徐々に枚数を増やします。音程の上昇・下降を左右の配置に反映し、速い連続音は左右に振り分けます。同一レーンの3連打・同時押しはなく、同一レーンの判定範囲が重ならないことを検証しています。
- `js/analyze-melody.cjs`：再生成時のみ使用する旋律解析。4096点FFT・10ms間隔で高音域のスペクトル変化と音程候補を調べ、低音の伴奏の影響を抑えて旋律の出だしを推定します。混合音源からの推定のため、主旋律だけを完全に分離・採譜したものではありません。実際の試聴による一致確認は未実施です。

音源はfetchとdecodeAudioDataで一度読み込み、AudioBufferを再利用します。AudioBufferSourceNodeを音楽開始時刻に予約し、音楽開始・カウントイン終了・ノーツ判定・曲終了をAudioContext.currentTimeで管理。描画はrequestAnimationFrameで現在時刻から位置を求めます。中断はAudioContext.suspend/resumeで音源ごと停止。リトライ時は全発音ノード停止と描画キャンセルを行い、新しい音源ノードで先頭から再生します。動画はミュートのままで、動画の再生時刻は判定には使いません。WAVの取得・デコードに失敗した場合は案内を表示してタイトルに戻り、再試行できます。

画像・動画が読み込めなくても続行可能です。動画失敗時はPNG、両方失敗時は仮表示になります。右下に素材の読み込み状況を表示します。

## 検証結果

実施済み：

- ローカルHTTPサーバーを起動し、HTML・CSS・JavaScript・画像・動画の配信を確認。
- 実際のgame.jsをDOM・AudioContextのモック環境で実行。開始から結果、Perfect/Good/Miss、判定境界（±160ms、80ms）、範囲外入力、同一ノーツへの重複得点防止を確認。
- キーリピート無視、左右入力、pointerdownとclickの重複防止、150ノーツ全Perfectで15000点・最大150コンボを確認。
- 中断中の時計停止・入力無効、再開時の時計維持、タブ非表示イベントによる中断、リトライ・タイトル復帰時の発音と描画の破棄を確認。
- 画像・動画のerrorイベント後も仮表示で開始から結果まで進行することを確認。
- WAVへの変更後、モックで音源の読み込み・キャッシュ・ループ指定・再生予約時刻・終了時刻、中断再開で音源を増やさないこと、リトライで先頭から再生すること、file://・HTTPエラー・デコード失敗後の復帰を確認。
- FFmpegで元のAACを正常にデコードしWAVに変換。WAVの全区間デコードとHTTP配信も確認。変換ツールは開発時のみ使用し、ゲームの実行には不要です。
- 連続音源は元音源の0.11〜9.11秒を使用。9・18・27・36・45・54秒で、重なりなく次の一巡へつなぎます。63秒の長さ、全50ms区間に無音がないこと、クリッピングがないことを数値検証し、ゲームの進行・中断・リトライのモックテストも再実行しました。

未確認：

- 検証用ブラウザーが利用できなかったため、実ブラウザーでの画面表示、実際の音質・音量、動画デコード、タッチ操作、スマートフォン実機の表示・音声遅延は未検証。
- 一時停止・再開の実音との同期もモックによるロジック検証のみです。Bluetooth機器などの出力遅延補正は実装していません。
- WAVの実ブラウザーでのデコード・試聴、ループ境界の聴感、実機の出力遅延を含む体感の一致は未確認です。旋律の出だしは高音域の解析から推定しています。

画像・動画・WAVはすべて存在しており、不足はありません。

## ファイル整理

音源ファイルは最後の一巡を切らずに収めた63秒です。ゲームは1.05倍速・157.5 BPMで最後まで再生し、60秒で終了します。判定時刻・カウントインも同期しています。カウントイン約2.29秒は別枠です。再生速度の変更により音程も少し高くなります。

画像・動画は `assets/` に集約し、直下の同一コピーを削除しました。音声の内容が一致することを確認したうえで、未使用のM4Aを削除し、再生成元を `source/joker_movie.wav` に一本化しました。ダウンロードしたFFmpeg本体・ZIP・付属ファイルを含む `.tools/` と、それだけを対象にしていた `.gitignore` も削除済みです。音源・譜面の再生成と自動テストはNode.js標準機能のみで実行できます。
